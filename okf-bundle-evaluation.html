3.2 Observations

  • Inside a frontier model's memory, the bundle removed the residual errors: wrong success status (200 vs 204) in 5 of 5 no-docs share answers, wrong permissions shape, wrong filter key, and 3–5 "unsure" flags per answer.
  • Public documentation via web search scored 91%: it copied the docs' ?CONFIG= cURL sample for POST (accepted by the server, but not the documented form body) and, on the edge case, asserted that a three-view share with a row filter works (fails with 7541) and that emailIds is mandatory (it is not).
  • For open models the bundle is the difference between unusable and correct: 51% → 98% and 19% → 100%; the no-docs answers invented paths, JSON bodies, a Zoho-orgid header and non-existent scopes.

7. Threats to validity

  • Single runs per cell in the chain. Variance across repeated runs was measured only in the share task (5 no-docs runs, spread 5.5–7). Directionally consistent, not a confidence interval.
  • Frontier-model prior knowledge. Claude Opus already knows much of this API; its no-docs errors are residual (status codes, key shapes, hedging), not gross. The large effects are on Sonnet, Haiku and the open models.
  • Error-diagnosis prompts include the API's summary constant, as the real API does; this makes "what does 7301 mean" easier than a bare code would be.
  • Open-model coverage is uneven: free-tier rate limits cut Ling to four tasks and dropped Gemma-4, Nex and Nemotron-Nano entirely (all such cells are marked and excluded).
  • Bundle trust tier is unverified; this evaluation confirmed the share-related facts against the live service (Experiment D) but not the rest of the 168 endpoints.
  • Environment: a development org; one policy difference was observed (a share to a non-member address was accepted).
