Recipes by tool

Pick your tool. Each recipe is self-contained and uses the exact wording the evaluation ran with.

Claude Code

Clone the bundle into (or next to) your project and add these lines to CLAUDE.md. This is verbatim what the live evaluation used; it works with file tools alone.

git clone https://github.com/sathish-dev-git/zoho-analytics-okf.git

# CLAUDE.md
The Zoho Analytics REST API v2 OKF bundle is in ./zoho-analytics-okf/okf/ and is the source of
truth for API semantics: filter criteria grammar (okf/foundations/filter-criteria-syntax.md),
import options (okf/domains/data-operations/sync-data-import/), row APIs, sharing

Any LLM through an API — OpenRouter, Ollama, vLLM, Bedrock, Vertex…

No agent framework needed. Put the documents an agent would open into the prompt and ask the question. This is exactly how the open models were evaluated (Nemotron-3 120B: 51% → 98%; Ling-3.0 Flash: 19% → 100%).

# python — works with any OpenAI-compatible endpoint (OpenRouter, Ollama, vLLM, LM Studio …)
import json, os, urllib.request
OKF = "zoho-analytics-okf/okf"                       # git clone https://github.com/sathish-dev-git/zoho-analytics-okf
def doc(p): return open(f"{OKF}/{p.lstrip('/')}", encoding="utf-8").read()
def error_entry(code):
    s = doc("/foundations/error-codes.md"); i = s.find(f"## Error {code}\n"); return s[i:s.find("\n## Error ", i+5)]

question = "Share view 123 in workspace 456 with jane@example.com read-only, rows where Region='East'. Then explain error 7301."
context = "\n\n".join([
    f"===== {p} =====\n{doc(p)}" for p in [
        "/how-to-use-this-bundle.md",
        "/workflows/share-view-with-row-filter.md",
        "/domains/share-and-publish/sharing/share-views.md",
        "/foundations/filter-criteria-syntax.md"]] +
    [f"===== /foundations/error-codes.md (excerpt) =====\n{error_entry(7301)}"])

body = {"model": "nvidia/nemotron-3-super-120b-a12b:free", "temperature": 0.2, "messages": [
    {"role": "system", "content": "Use ONLY the supplied bundle documents as the source of API facts. Quote the document path for each fact."},
    {"role": "user", "content": context + "\n\n===== TASK =====\n" + question}]}
req = urllib.request.Request("https://openrouter.ai/api/v1/chat/completions", json.dumps(body).encode(),
      {"Authorization": "Bearer " + os.environ["OPENROUTER_API_KEY"], "Content-Type": "application/json"})
print(json.load(urllib.request.urlopen(req))["choices"][0]["message"]["content"])
# Ollama, one-liner: a local model with the endpoint document in context
ollama run llama3.1 "$(cat zoho-analytics-okf/okf/domains/share-and-publish/sharing/share-views.md)

Using only the document above: give the HTTP method, path, headers, CONFIG and scope to share view 123 read-only to jane@example.com."

Which files to include? Follow the bundle's own navigation rules (below): endpoint document for facts, workflow for multi-step jobs, request-conventions.md for encoding, the error-catalog entry for a failure. Or let the model choose: give it how-to-use-this-bundle.md plus the file list and ask for the 3–4 paths it needs, then send those — the "self-navigated" condition in the evaluation scored 8/8 both times on a 120B open model.

Package it as an Agent Skill

The Agent Skills layout (used by Claude Code, Cursor and others) is a folder with a SKILL.md. The bundle is the references/ content; the skill tells the agent when and how to read it.

~/.claude/skills/zoho-analytics-api/          (or ~/.cursor/skills/…)
├── SKILL.md
└── references/okf/   → symlink or copy of zoho-analytics-okf/okf

# SKILL.md
---
name: zoho-analytics-api
description: Use when writing or debugging code that calls the Zoho Analytics REST API v2 — requests, CONFIG payloads, scopes, error codes, multi-step workflows.
---
Source of truth: references/okf/. Read references/okf/how-to-use-this-bundle.md first.
- Building a request: endpoint document frontmatter (method, path, config_parameter.location, oauth_scopes,
  success_status) + references/okf/foundations/request-conventions.md for encoding.
- Multi-step task: start in references/okf/workflows/.
- A call failed: references/okf/foundations/error-codes.md#error-<code> — meaning, HTTP status, fix.
- Never guess a key name or path; if the bundle does not say, say so.

RAG pipelines and internal copilots (support, Zia-style assistants)

The bundle is pre-chunked: ~500 files, each one concept, each with typed YAML frontmatter. Index files, not fragments, and use the frontmatter as metadata filters.

# python — index the bundle with frontmatter as metadata (LangChain shown; any vector store works)
import glob, yaml, re
from langchain_core.documents import Document
docs = []
for path in glob.glob("zoho-analytics-okf/okf/**/*.md", recursive=True):
    text = open(path, encoding="utf-8").read()
    m = re.match(r"^---\n(.*?)\n---\n(.*)$", text, re.S)
    meta = yaml.safe_load(m.group(1)) if m else {}
    api = meta.get("api", {}) or {}
    docs.append(Document(page_content=m.group(2) if m else text, metadata={
        "path": path.split("/okf/", 1)[1], "type": meta.get("type"), "title": meta.get("title"),
        "operation_id": api.get("operation_id"), "method": api.get("method"), "http_path": api.get("path"),
        "scopes": ",".join(api.get("oauth_scopes", []) or []), "error_codes": ",".join(map(str, api.get("error_codes", []) or []))}))
# retrieval tips: filter type=="API Endpoint" for how-to questions; look up error codes by anchor, not by similarity:
#   okf/foundations/error-codes.md#error-7301  → deterministic answer for "why am I getting 7301?"

For support assistants the two highest-value lookups are deterministic, not semantic: error-codes.md#error-<code> (meaning, status, fix, which operations raise it) and permission-matrix.md (scope + role per endpoint).

Build your own tool surface: bundle + one generic call

An MCP server hard-codes one tool per operation. The bundle lets you skip that: give the agent one generic HTTP tool and the bundle as knowledge, and it composes any of the 168 endpoints itself. This is what the live evaluation did (the "REST wrapper"), and it worked on the smallest model tested.

THE PATTERN

One tool, all endpoints

The tool only adds what the agent must not know — the token and the org header. Method, path and CONFIG come from the bundle. Wrap it as an MCP server, a LangChain tool, or a function call and you have a full-API "personal MCP" that stays current every time the bundle is regenerated.

# minimal generic tool (python, OpenAI-style function schema)
import requests, os
def zoho_analytics_call(method: str, path: str, config: dict | None = None, files: dict | None = None):
    """Call the Zoho Analytics REST API v2. Take method, path, CONFIG shape and location from the OKF bundle."""
    url = "https://analyticsapi.zoho.com" + path
    h = {"Authorization": "Zoho-oauthtoken " + os.environ["ZA_TOKEN"], "ZANALYTICS-ORGID": os.environ["ZA_ORG"]}
    import json
    if files:   r = requests.request(method, url, headers=h, data={"CONFIG": json.dumps(config or {})}, files=files)   # multipart imports
    elif method == "GET": r = requests.get(url, headers=h, params={"CONFIG": json.dumps(config)} if config else None)
    else:       r = requests.request(method, url, headers=h, data={"CONFIG": json.dumps(config or {})})                 # form field CONFIG
    return {"status": r.status_code, "body": r.text[:4000]}
WHAT THE AGENT DOES WITH IT

Reads, then calls once

Asked to "share table X read-only to Jane, rows where Region = East", an agent with the bundle opens workflows/share-view-with-row-filter.md → share-views.md, then calls:

zoho_analytics_call("POST", "/restapi/v2/workspaces/{ws}/share",
  {"viewIds": ["{view}"], "emailIds": ["jane@example.com"],
   "permissions": {"read": true},
   "criteria": "\"Region\"='East'"})          → 204
zoho_analytics_call("GET", "/restapi/v2/workspaces/{ws}/share/shareddetails",
  {"viewIds": ["{view}"]})                    → criteria stored, isInvalidCriteria:false

Without the bundle the same agents tried /shares/tables, emails, permission:"VIEW", filterCriteria:{…} — 8542, 8504, 8525 — and two of them shared without the filter first.

GUARDRAILS

Keep the agent honest

Three lines that made the evaluated runs safe: "never guess a key name or path — if the bundle does not say, say so"; "verify with the read endpoint the playbook names before reporting success"; and for destructive steps, "state the criteria string before executing it". Pair with the smallest OAuth scopes the endpoint documents list — they are in every frontmatter.

From how-to-use-this-bundle.md. Tell an agent to follow these and it finds the right file in one or two hops.

FAQ

Do I need the whole bundle in context?

No. Agents open 3–6 files per task (5–21k tokens). For direct API calls, include the endpoint document, the workflow if multi-step, and the error entry if debugging — or let the model pick files from how-to-use-this-bundle.md plus the file list.

Which models does it work with?

Anything that reads text. Evaluated: Claude Opus, Sonnet, Haiku (agentic), Nemotron-3 Super 120B and Ling-3.0 Flash (direct calls). The smaller the model, the bigger the gain.

Is it a replacement for the MCP server or the SDKs?

No — it is what they, and any agent, read to make the right call. Tools execute; the bundle knows. Together they cover the whole API with one generic executor.

How current is it?

Generated from the API reference and OpenAPI specs; manifest.json carries the version and generated.at. Trust tier is currently unverified (faithful to the docs, not yet re-confirmed line by line against the live service); the share endpoints were verified live in the evaluation.

Does it expose customer data or internals?

No. Every fact comes from the public API reference and OpenAPI files; the validator refuses any provenance link pointing outside the bundle.

Where do I report a wrong fact?

Open an issue on the repository with the bundle version from manifest.json and the document path. Reviewers can add verified entries to concepts they confirm.
